## lecture 09 - Processes & System Resource Management 

- program: executable code stored on disk
- process: instance of the program
    - every process has its own PID (process ID)  
    - may also have its own __PPID__ (parent process ID)  
    - allows viewing of: 
        - "which process do i want to inspect?"
        - "which proces is consuming resources?"
        - "which process do i need to terminate?"

- __ps__ can show: 
    - pid
    - tty (associated terminal) 
    - time - cpu time 
    - cmd - command/program 

- can have __sleep__ command run in background via: 

```
sleep 300 & 
``` 

- __ps aux__ returns: 
    
    ```
    owner process_ID parent_process_ID cpu_usage uptime  
    ```
- usage examples: 
    - __ps -ef__ 
    - __ps aux__ 


- to see particular process: 
    ``` 
    ps aux | grep process_name 
    pgrep process_name
    pgrep -l process_name 

    (ex). pgrep -l sleep 
    ```

- __real-time monitoring__ 
 - __top__ 
    - shows a continuous display of all running processes, CPU activity, mem usage, load info, process state 
      all in __real time__  
 
 ```
 State     Meaning 
 -----     ------- 

 R         running
 S         sleeping 
 T         stopped   
 Z         zombie process
 ``` 


- to stop a running process:  
    - as a sysAdmin, should rarely (if ever) kill a running process  
     
```
kill PID 
```
    
- other methods of stopping running data: 
    - __SIGTERM__ 
        - send signal to terminate a process  
        - signal number: 15 
        - ran by default when you run kill pid  
        - kill process with normal priority
    - __SIGKILL__ 
        - signal number: 9
        - kill signal __immediately__ 
        - "force" kill 
        - bad habit
