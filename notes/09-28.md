## lecture 11 - services & systemd

- how does linux manage long-running system services? 

- service: long running program that provides system function
    - (ex). 
        - ssh
        - time sync 
        - printing 
        - logging
        - networking 
    - may continue running for days, wks, months 

- process vs. service 
    - process:
        - running program
        - ps 
        - PID 
        - ssh process

    - service: 
        - managed system function
        - systemctl
        - unit name 
        - sshd.service  

- __systemd__
    - system & service manager used by modern RHEL systems 
    - can (services): 
        - start
        - stop 
        - restart 
        - start auto at boot
        - track deps
        - maintain service state  
    - command used: __systemctl__ 
    - managed objects called __units__ 
        - (ex.) 
            - .service 
            - .socket
            - .target
            - .timer
            - .mount  

- to display service units currently loaded: 
   
   ```
    systemctl list-units --type=service

    OR 

    systemctl list-unit-files --type=service
    ```
- to search for a particular service: 
    
    ``` 
    systemctl list-unit-files --type=service | grep ssh
    ``` 
- to view status of a particular service: 
    
    ```
    systemctl status service-name
    ```

- to activate/deactive a particular service: 

    ```
    systemctl start sshd.service 
    
    systemctl stop ssh.service
    ``` 
- to view activity state of a particular service: 

    ```
    systemctl is-active service-name
    ```
- __good practice:__ 
    - don't stop a service before verifying its safe to do so



- restarting vs reloading services: 
    - restart:
        - stop & start 
    - reload: 
        - re-read config file (if supported) 
        - not every service supports reload 

        ```
        sudo systemctl reload service
        ```
- enabled vs disabled services  

    ``` 
    sudo systemctl enable/disable service-name
    systemctl is-enabled service-name
    ```
    - enabled
        - started upon system boot

    - disabled 
        - config'd to start manually   
        - service will be 'off' upon next boot



- find __failed__ services
    
    ```
    systemctl --failed 
    ``` 
    - inspect respective process: 

    ```
    ps -fp PID
    ``` 

- __reloading__ a service: 
    - useful when modying service config 
    

- core systemctl commands: 
    - systemctl status service 
    - systemctl start service
    - ... stop service 
    - ... restart service
    - ... reload service 
    - ...
